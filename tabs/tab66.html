Empty Roles

Tab 66

Lists the roles of the hierarchy with their users, when they were emptied, and what still names them, so that roles nobody uses any more can be deleted safely. Typical use: after a reorganisation, find the roles left without active users, check what still references them, and delete the ones that are truly abandoned.

★ Key features

  • Role hierarchy with parent, depth, child count and active / inactive user counts
  • Emptied: date the last user left the role and how many users left, read from the Setup Audit Trail
  • Created: creation date, when it falls inside the audit trail window
  • Referenced by: sharing rules, queues, public groups, approval processes and workflow email alerts that still name the role; click the number for the list
  • References from the dependency graph (instant) or from a live metadata retrieve (free, about 2 minutes on a large org)
  • Can Delete takes both active users and live references into account
  • Delete never runs blind: references are checked first, then two warnings (still referenced, changed in the last 30 days) with Cancel as default

How it works

The status line

cached at 02/10 09:14 - audit trail since 2026-04-05 - references: dependency graph 02/10 09:15 says when the roles were loaded, how far back the Setup Audit Trail goes, and where the references came from and when. If the audit trail cannot be read (it needs the user's language set to English), the line says so instead of showing a date.

Emptied and Created: a 180-day window

Salesforce keeps the Setup Audit Trail for about 180 days. An empty Emptied or Created cell means nothing happened in that window, not that it never happened. The audit trail names roles by their label only, so two roles sharing the same name get no audit trail data.

Referenced by

  • Counts what still names the role: sharing rules, queues, public groups, approval processes, plus workflow email alerts that mail the role.
  • ? means nobody has looked yet. It is not "nothing".
  • (+N inactive) counts approval processes that are switched off. They are shown, but they do not block deletion.
  • Clicking the number opens a popup: type, name, how it names the role, and an Active column only when one referrer is inactive.

Two ways to get the references

  • Dependency graph (licensed feature): instant, if the graph was built recently enough to know roles. A graph built before roles were supported is not used, because it would wrongly say that nothing names any role.
  • Live check (free): otherwise, Check references retrieves the approval processes, sharing rules, queues and public groups from the org, read-only. It takes about 2 minutes on a large org.

Can Delete

A role is deletable when it has no active user and, once the references are known, nothing live still names it. A role referenced only by inactive approval processes stays deletable.

Deleting

  • If the references are unknown, the screen looks them up first.
  • It then warns about roles still referenced, then about roles changed in the last 30 days according to the audit trail. Cancel is the default each time.
  • Deleting a role also deletes the roles below it; the warnings cover those too.

A note on reorganisations

A role left empty after a reorganisation may be very recent: users may be moving back, or the new structure may not be finished. Look at the Emptied date before deleting.
