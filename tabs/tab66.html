★ Key features

  • Role hierarchy with parent, depth, child count and active / inactive user counts
  • Show pills: All, Deletable (selected by default), Blocked, Recently changed, each with its count
  • Emptied (users left): date the last user left the role and how many users left, read from the Setup Audit Trail
  • Created: creation date, when it falls inside the audit trail window
  • Referenced by: sharing rules, queues, public groups, approval processes and workflow email alerts that still name the role; click the number for the list
  • Can Delete shows Deletable or Blocked, taking users, child roles and references into account
  • Rows changed in the last 30 days carry a "recent" badge
  • Delete never runs blind: references are checked first, then warnings (still referenced, changed in the last 30 days) with Cancel as default

How it works

The status line

cached at 19/11 09:14 - audit trail since 2026-05-23 - references: live check 19/11 09:17 says when the roles were loaded, how far back the Setup Audit Trail goes, and when the references were checked. If the audit trail cannot be read (it needs the user's language set to English), the line says so instead of showing a date.

Emptied and Created: a 180-day window

Salesforce keeps the Setup Audit Trail for about 180 days. An empty Emptied or Created cell means nothing happened in that window, not that it never happened. The audit trail names roles by their label only, so two roles sharing the same name get no audit trail data.

Referenced by

  • Counts what still names the role: sharing rules, queues, public groups, approval processes, plus workflow email alerts that mail the role.
  • ? means nobody has looked yet. It is not "nothing".
  • (+N inactive) counts referrers that are switched off. They are shown, but they do not block deletion.
  • Click the number to open a popup listing type, name and how it names the role.

Check references

The button retrieves the approval processes, sharing rules, queues and public groups from the org, read-only. It takes about 2 minutes on a large org; a progress bar replaces the pills while it runs.

Can Delete

A role is deletable when it has no user, no child role and, once the references are known, nothing live still names it.

Deleting

  • If the references are unknown, the screen looks them up first.
  • It then warns about roles still referenced, then about roles changed in the last 30 days. Cancel is the default each time.
  • Deleting a role also deletes the roles below it; the warnings cover those too.

A note on reorganisations

A role left empty after a reorganisation may be very recent: users may be moving back, or the new structure may not be finished. Look at the Emptied date before deleting.
