★ Key features

  • Display queries every sandbox of the connected org via the SandboxInfo Tooling API: name, license type, description, last modified date and user, activation user group and source sandbox.
  • New Org (enabled once a row is selected) opens the org configuration pre-filled with the sandbox name and a derived username (base.sandboxname). If a config with that username already exists, it opens in edit mode instead.
  • Create sandbox queues a new sandbox in the production org. It needs the Manage Sandboxes permission and a free licence of the chosen type. The form lets you pick the license type, a description, the activation user group and optionally a source sandbox to clone. The new sandbox shows up in the list once the org lists it.
  • Refresh sandbox queues the refresh of the selected sandbox. It is overwritten by a copy of its source, so you must type the sandbox name to confirm.
  • Delete sandbox deletes the selected sandbox and frees its licence. This is irreversible and you must type the sandbox name to confirm. If an org config in Calumet still points at it, you are offered to delete that config too.
  • Last Modified Date is flagged with a warning marker when older than 6 months, and with a stronger marker after 1 year and 2 years.
  • Color-coded badges give each user, activation group and source sandbox its own color; rows are tinted to match the user who last modified the sandbox.
  • Filter searches the name, description, license type, user, group and source columns (contains, case-insensitive). The counter shows shown / total.
  • Create, Refresh and Delete only work on a production org. On any other org the message “Only works for production org” is shown and these buttons are disabled; Refresh and Delete also need a selected sandbox.
